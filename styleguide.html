Colour

Six world hues, three semantics, one neutral chrome. Text steps are solved to clear 4.5:1 and stroke steps 3:1 against every surface they can composite onto — the page, cards, sunken panels and their own tint — not just the page background.

Elevation and the affordance rule

Inside the content area, raised means touchable and flat means not. Reviewing a screen is checking that rule holds. Shadows are built from a fixed dark --shade and a fixed light --rim, never from --ink, which inverts between themes and would paint a pale halo under every dark-mode card.

Press any raised sample: it sinks to --e-press within --t-state. That is role 3, and it is the only feedback a child needs to know the tap landed.

Icons

Path data in a JavaScript module, not an SVG sprite. Sized in em so they track the text beside them at every level. Every one is decorative and paired with a label — nothing here is an icon-only control, because an icon-only control is a guessing game for a five-year-old.

Lesson parts

The phase 4 components. Each exists because it has behaviour that plain HTML plus a class cannot express — anything that did not clear that bar stayed CSS.

Placement — <fp-board>, <fp-placeable>, <fp-slot>

Nielsen Norman's developmental research is blunt: children aged 5–7 struggle with dragging, and precise dragging stays hard well past that. So drag is not the interaction — it is an enhancement over one state machine. Tap a part, then tap a slot. Or press Enter twice. Or drag. All three call the same two methods, which is also how the keyboard and screen-reader paths came for free rather than as a retrofit.

Parameter — <fp-slider>

Wraps the native range input rather than rebuilding one, so keyboard, screen-reader semantics, touch handling and OS accessibility settings all come from the platform. The wrapper adds a visible label, a live readout in the child's units, and a hit area that meets the level's touch minimum.

Prediction — <fp-predict>

The pedagogical core, and the smallest component here. Sinha & Kapur found the highest-value feature of problem-solving-first teaching is instruction that visibly builds on the learner's own answer (g = 0.56). Here that is string interpolation. Commit to a prediction, then run it — a wrong answer gets the discovery colour, not the failure colour, because that is the moment the lesson works.

Disclosure — no component

The blueprint listed an <fp-reveal>. Native <details> already does action-gated disclosure with keyboard support, screen-reader semantics and find-in-page, and lesson code can open it by setting one attribute. Deleted rather than written.

Why does the membrane let some things through?

Because it is built from molecules with a water-loving end and a water-hating end, and that arrangement is picky about what can slip between them.
